# iOS AI 가계부 v2 — 제품 계약과 1차 구현 범위

> 최신 변경: 자체 서버·Windows 중계 없이 아이폰 단독 운용. 최소 버전은 iOS 17이며 iPhone 16 Pro의 iOS 18(2024)·iOS 26(2025)·iOS 27(2026)을 단일 빌드 대상으로 삼습니다. 기본 Gateway 모드는 제거했고 개인 API 직접 연결/기기 내 결산만 유지합니다. 설치·갱신은 iloader/SideStore 흐름입니다.

> 개인정보: 원문 저장 전 카드번호·부분 카드번호·전화번호·계좌번호·보안코드를 마스킹합니다. 원문 지문은 SHA-256으로 보관하고 기존 원문 장부·백업을 변환합니다. 마스킹은 알려진 형식에 대한 방어이며 임의의 모든 개인정보 형식을 완벽히 탐지한다고 보장하지 않습니다. 승인·취소·환불은 서로 다른 이벤트이며 원승인 행을 지우지 않습니다. 원거래가 유일하면 부분취소도 누적 취소/환불 한도 내에서 반영합니다.

## 사용자 경험

앱 설치 → 예상 월급·고정비·저축 목표 → 카드사 선택/추가 → 월급 확인일·시간·결산 시간·주간 마감 요일 → AI 전송 동의 → 알림 허용 → 카드별 Wallet/SMS/이메일 자동화 → 시간 자동화 → 위젯 추가.

일상적인 개입은 월급 확인, 고정비 변경, SMS에 없는 수입/지출 입력입니다. 앱이 사용자에게 코드·JSON·정규식·개발 도구 조작을 요구하지 않습니다.

개인 자동화와 홈 화면 위젯 배치는 사용자가 iOS에서 완료해야 합니다. 앱은 안내 완료와 실제 실행 확인을 구분합니다. App Intent 등록 자체는 문자 자동화 생성이 아닙니다. iOS에 별도의 ‘위젯 데이터 공유 권한’ 팝업은 없으며 App Group은 개발자가 설정합니다.

## 장부와 예산

- 기준: KRW 정수, Asia/Seoul, 달력 월. 월급 확인일과 장부 기간은 별개입니다.
- 예상 월급은 예산 계획에만 사용합니다. 실제 수입 대비 지출률의 분모는 기록된 실제 수입입니다. 분모 0이면 비율을 표시하지 않습니다.
- 월급 확인은 해당 월의 단일 급여 기록을 대체합니다. 추가 수입은 별도 거래입니다.
- 고정비/구독 예약은 예산 확보이며 납부 사실이 아닙니다. 실제 거래가 연결되면 총지출에는 포함하고 변동 생활비에서 다시 차감하지 않습니다.
- 고정비 초과액은 남은 생활비에서 차감합니다. 다른 미납 고정비 예약으로 초과액을 가리지 않습니다.
- 수동 입력의 고정비 연결 기능으로 월세·계좌이체를 기록합니다.
- 현 버전은 설정의 월별 이력 없이 현재 설정을 사용합니다. AI에는 이를 ‘현재 월간 예산 참고값’으로 전달하며 과거 예산 달성률을 단정하지 않습니다. 월별 설정 스냅샷은 후속 항목입니다.

## 카드 거래 수집

사용자가 앱에서 카드사를 켜거나 이름과 감지어를 직접 추가합니다. 수집 우선순위는 Wallet Transaction 자동화 → 카드사 SMS/이메일 자동화 → 푸시 화면 캡처 OCR/텍스트 붙여넣기 → 수동 거래입니다.

- `RecordWalletTransactionIntent`: 지원 카드의 Wallet 거래 트리거가 넘긴 원화 금액·가맹점을 즉시 기록.
- `RecordMessageIntent`: 메시지/이메일 자동화의 본문과 선택 카드사를 공유 파서로 전달.
- 푸시 화면 가져오기: PhotosPicker로 사용자가 고른 캡처를 Vision에서 기기 내 OCR. 이미지와 OCR 원문은 장부·백업·AI에 저장하거나 전송하지 않음.
- 일반 앱은 다른 카드사 앱의 푸시 본문을 백그라운드에서 읽을 수 없음. Notification Service Extension은 자기 앱용 원격 알림에만 동작하므로 직접 감시 기능으로 표시하지 않음.

- 현재 샘플 기반 보수적 정규식. 카드사명·승인 이벤트·단일 원화 금액·상호가 모두 확인되는 형식만 자동 반영.
- 누적/잔액 제외. 해외통화, 복수 금액, 거절/예정, 모르는 상호 위치는 원문과 함께 검토함 보존.
- 당일 정규화한 문자 지문으로 중복 차단. 식별번호 없이 본문이 완전히 같은 실제 결제 두 건은 구분이 안 될 수 있음. 승인번호 추출은 실제 문자 샘플 확보 후 확대.
- 취소는 최근 90일 동일 카드/상호/금액의 미취소 승인 1개가 유일한 경우에만 반영. 부분취소와 모호한 취소는 검토함.
- 미확정 금액을 임의로 지출/환불에 넣지 않음. 수동 보완 처리 시 기존 문자 지문을 유지하여 재수신 중복 방지.
- 다른 앱 알림, 과거 SMS 전체, 은행 거래내역을 몰래/일괄 읽는 기능은 없음.

## 네 가지 결산

| 주기 | 기준 | 전달할 정보 |
|---|---|---|
| 야간 | 설정 시간의 오늘 기록 | 실제 수입/지출, 분류 합계, 전일 비교 |
| 주간 | 설정한 요일 종료, 최근 7일 | 주간 합계, 직전 7일 비교 |
| 월말 | 달력 월 마지막 날 | 월간 합계, 직전 달 비교, 현재 예산 참고 |
| 연간 | 12월 31일 | 12개월 수입/지출, 전년 비교 |

모든 기간의 숫자는 앱이 계산합니다. 모델은 관찰·설명·실행 제안을 반환합니다. 무지출로 관측되더라도 ‘기록된 거래 없음’으로 표현하며 실제 무지출을 단정하지 않습니다.

22시 결산은 잠정값입니다. 마감 시간 뒤 거래를 포함하도록 후속 실행에서 해당 기간을 재집계합니다. 동일 집계 지문이면 AI 응답을 재사용하고 변경되면 무효화합니다. 현재 자동 복구 범위는 최근 7일, 직전 월, 직전 연도입니다. 그보다 오래된 수정은 후속 재결산 UI에서 처리할 수 있도록 확장 필요.

한 번의 시간 자동화가 모든 마감일을 판별합니다. 숫자 결산을 먼저 저장하고 최대 12개의 대기 결산을 한 번의 AI 요청으로 묶습니다. 요청이 실패하거나 iOS가 작업을 중단하면 저장된 숫자 결산을 유지합니다. 정확한 완료 시각·무중단 실행은 보장하지 않으며 기기에서 검증해야 합니다.

## AI 제공 방식

- 개인 API: 앱 → 사용자가 선택한 Groq/OpenRouter/Gemini. 키는 ThisDeviceOnly Keychain.
- 전송 동의 없음/AI 끔/공급자 장애: 기기 내 규칙 분석.
- 공급자/모델 교체는 공통 요청·응답 계약과 어댑터로 격리.
- 자동으로 다른 회사에 개인정보를 재전송하지 않음. 향후 백업 공급자를 넣으면 허용된 목록과 데이터 처리 안내를 먼저 설정.
- 전송: 기간, 수입/지출 합계, 고정된 분류명별 합계, 이전 기간 합계, 월별 합계, 검토함 개수, 현재 예산 설정.
- 미전송: 원본 SMS, 가맹점명, 개인 메모, 카드/계좌번호, 이름, 전화번호.
- 공급자 응답 JSON과 길이를 검증. JSON 형식 준수는 내용의 정확성 보장이 아니므로 숫자 UI는 앱 계산값만 표시.
- 무료 서비스 한도는 계정/조직 전체에 적용되므로 사용자 수만큼 공짜 쿼터가 생기지 않음. 보장 없는 무료 한도를 무제한 제공으로 광고하지 않음.

## 저장과 보안

App Group 로컬 JSON을 NSFileCoordinator로 직렬화하고 atomic write. 직전 정상본을 백업. 손상된 장부를 발견하면 빈 장부로 덮어쓰지 않고 오류 표시. 클라우드 동기화, 자동 복원, 서버 장부 보관은 아직 없음.

`gateway/`는 초기안 검증용 참고 구현이며 현행 앱이 호출하지 않습니다.

## 미검증·후속 작업

- Xcode 컴파일과 XCTest 실행, 실제 잠금 상태 자동화 및 위젯 검증.
- 실제 개인 API 키로 Groq/OpenRouter/Gemini 호출과 한국어 결과 평가. 현재 연결된 공용 키는 없음.
- 실제 카드별 Wallet/SMS/이메일 자동화와 푸시 캡처 OCR 인식률 확인.
- 실제 문자 샘플로 카드사·체크카드·부분취소·할부·해외거래 확대.
- 거래 편집, 검토함 무시 처리, 설정 이력과 백업 복원 UI.
- 앱 아이콘, 시각 디자인 다듬기, VoiceOver/Dynamic Type 검증.
- App Store/사이드로드 배포 및 서명 경로 결정. iloader 등 설치 도구의 App Group 지원 검증.
